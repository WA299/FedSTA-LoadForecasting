## Technical route

The original G1 ST-FedNet remains GAT (2 heads and self-loops) -> single-layer GRU -> single-head Additive Temporal Attention -> Linear. G1.1 adds a separate `stfednet_residual` variant: GAT -> Linear back to one channel -> `x + alpha * spatial`, with learnable scalar alpha initialized to 0.05 -> the same GRU/temporal attention/output head. Do not change old G1 model shapes or checkpoints. Both use hidden dimension 32, dropout 0.1, 48-to-1 windows; preserve configurable G0 48-to-24 preprocessing. Later phases add FedAvg, FedProx, DP-SGD and epsilon/utility analysis.

## Federated design

There are five clients: the four LV reference grids and the industrial MV/LV grid. Each client keeps its own variable-size graph and load mask. Central coordination receives model updates only; client data and topology remain local. The common model interface must support variable `num_nodes` and a per-client `edge_index`.

## Data interface

`src.data.loader` is the G0 source of truth. `GridData` exposes `load_matrix [8760, num_nodes]`, `edge_index [2, 2*num_physical_branches]`, `load_mask [num_nodes]`, hourly `timestamps`, `node_ids`, and `client_id`. `PreparedClient` exposes a training-fitted per-node `StandardScaler` and chronological `train`, `val`, and `test` window datasets. Windows have `X [48, num_nodes, 1]` and `Y [horizon_hours, num_nodes]` (G0 default 24, G1 configuration 1). Source physical values are in kW; window tensors are standardized. Use `inverse_transform` before reporting physical-unit metrics.

The four MATPOWER-style LV `p_load.csv` files are interpreted as MW and converted by `*1000` to kW. This unit is an explicit source-data assumption because the files do not carry a unit field. Industrial `Load_kWh` is hourly energy; numerically it equals average kW over a one-hour interval. Duplicate LV columns are summed by bus. Duplicate industrial timestamp rows are kept once when identical; conflicting repeats and missing hours are rejected.

## G3.0 DP feasibility only

G3.0 adds an isolated reference implementation in `src/privacy/per_sample.py`; it does not modify the G2 client/server loop or either frozen model. The protected record candidate is one complete graph window containing all 48 history hours and the forecast target over all nodes. Reduce masked Huber elements within each window, compute one gradient over all trainable parameters, clip that whole gradient before aggregation, add Gaussian noise to the clipped-gradient sum, then divide by the selected batch normalizer. Fixed-size final partial batches use their actual count; a future Poisson loader uses expected batch size and noise-only updates for empty draws. The current helper is a correctness/engineering tool only, not a production DP optimizer.

The current G2 loader uses fixed-size random shuffling and cannot use the Poisson-subsampled RDP examples in `results/g3_0/compatibility.json` as its accountant. Formal G3 must choose an accountant-consistent sampler and document adjacency, q, steps, C, sigma, delta, client composition, and secure randomness. Window-level privacy does not imply timepoint/user/client privacy: windows overlap; client curves may repeat; training-fitted scalers, topology/load masks, validation metrics and model selection need explicit treatment. No end-to-end privacy, secure aggregation or communication security claim is allowed.

Environment checks on Python 3.13.7 / PyTorch 2.10.0+cu126 / RTX 4060 Laptop GPU found Opacus 1.6.0 cannot directly process these formal models. It requires DPGRU; GRU per-sample gradient axes are `B*N` and conflict with batch-level attention/head gradients, while the Gated custom GAT fallback lacks `edge_index` handling. `torch.func` batched gradients fail on CPU in this runtime but work for both models on CUDA with cuDNN disabled; the GRU fallback is slower and has higher peak memory. The explicit window loop is the correctness oracle. See `docs/G3_0_DP_FEASIBILITY.md`, `results/g3_0/feasibility.json`, `scripts.check_dp_compatibility`, and `scripts.benchmark_per_sample_gradients`.

G3.0 validation: all 138 repository tests pass (14 new G3.0 checks); Batch32 CUDA measurements covered 39-, 80-, and 76-node grids for both models, all six method/model/grid cases completed without OOM, and bounded epoch estimates are in `results/g3_0/benchmark.json`. The installed Opacus secure mode is unavailable because `torchcsprng` is missing and no distribution is available in this Windows/Python environment. No DP optimizer is integrated, no formal DP training or test evaluation ran, and no epsilon is claimed for actual training. Await phase acceptance before implementing G3.

## G3.1 window-level DP-FedAvg

G3.1 is isolated in `src/fl/dp_server.py` and `src/privacy/{poisson,accountant,training,per_sample}.py`; it does not alter G1/G1.2 models or old G2 training. Each record is a complete 48-hour, all-node graph window plus its 1-hour all-node target. Under fixed topology, load mask and train-fitted scaler, use add/remove window adjacency. Each client independently samples every one of its 6084 windows with Poisson probability q=32/6084 per step; 191 nominal steps form one local epoch and 20 rounds imply 3820 accounted steps/client. Clip each whole-window, all-parameter gradient to C=1 before summing; add independent Gaussian noise with std sigma*C to the sum; divide by q*N=32. An empty draw still gets noise and one AdamW/accountant update. FedAvg weights model states by available training-window counts; no data/topology/scaler enters parameter aggregation.

CUDA `auto` uses torch.func only after actual clipped-gradient agreement with the explicit loop Oracle was tested for both supported models. It runs with cuDNN disabled around the native GRU and may emit PyTorch's slow fallback warning; unsupported operators raise and do not silently fall back. CPU `auto` uses the loop. A zero-sigma control returns epsilon null and is non-DP. Opacus 1.6.0 is used only for RDPAccountant, not its grad sampler or DPOptimizer. RDP state and actual step counters are stored separately per client; checkpoints include Poisson/noise generator states and can resume a committed local optimizer step without replaying it. AdamW resets each client-round but its state persists within that local epoch.

G3.1 Checkpoint optimization: default `checkpoint_every_steps=25` (`--checkpoint-every-steps 1` restores per-step saves). Do not clone model, AdamW, RNG or accountant state on uncommitted steps. Force atomic commits after each client's local work, after five-client aggregation, and after validation/Best selection. Only the last successfully atomically replaced `latest_dp_global.pt` is committed progress; e.g. an interruption after step 37 with a step-25 checkpoint must restore all model/optimizer/sampler/noise/Dropout/RDP state at 25 and replay step 26 onward. Use unique same-directory temp files with atomic replace for G3.1 checkpoints. The in-memory RDP accountant still advances after every completed noisy update; serialize state, query epsilon and write `privacy_accounting.json` at checkpoints/round boundaries only. Use `checkpoint_performance.json` for phase timing diagnostics. See `docs/G3_1_DP_FEDAVG.md` and `scripts/benchmark_dp_checkpoints.py`.

Only `research` mode is currently runnable, using ordinary PyTorch PRNG; its theoretical RDP ε is not a privacy claim. `privacy_claim` fails before data loading because no reviewed cryptographically secure Gaussian RNG is wired. Keep training/gradient diagnostics, validation results and validation-based checkpoint selection restricted: they are not protected outputs. The stated window adjacency is conditional on fixed preprocessing and does not imply timepoint/user/client or end-to-end privacy; overlapping windows, private scaler fitting, repeated cross-client curves, and public validation statistics require additional treatment. DP-SGD does not provide secure aggregation or communication encryption.

Use `configs/g3_1.yaml`, `python -m scripts.train_dp_federated --model stfednet_gated --noise-multiplier 1 --privacy-mode research --device cuda` (or `gru_attention`), and resume with `--resume <latest_dp_global.pt>`. σ=0.5/1/2/4 plans and optional σ=0 non-DP controls are listed in `docs/G3_1_DP_FEDAVG.md`. `python -m scripts.smoke_g31` performs one real Poisson step per client for both models with test access blocked. The G3.1 validation and Checkpoint optimization acceptance, benchmark results and runtime comparison are documented in `docs/G3_1_DP_FEDAVG.md` and `results/g3_1_checkpoint_optimization.json`. No formal 20-round run or test evaluation was performed; do not proceed to broader G3 methods without user acceptance.
